# v9: 既存ストローク語彙をAIが視覚選択する方式

## 目的

v8ではAIが参照画と途中画を見て次の描画意図を決めるところまでは有効でしたが、座標・幅・角度・本数までAIが直接指定したため、低レベルの幾何制御がモデル性能に強く依存し、顔の形や目などが崩れました。

v9では役割を分離します。

- AI: **何を直すか、どの種類の仕事をするか、候補A/B/Cのどれが人間らしいか**を判断する
- コード: v7で実際に使われた既存ストロークの座標・色・太さ・方向をそのまま再利用して候補を作る
- AIは座標を書かない
- 参照画像の画素誤差から候補を順位付けしない

## 固定するもの

最初の試行ではv7の `silhouette` と `light_shadow` を凍結した土台として使います。

これは「以前うまくいった大きな面の作り方」を資産として扱うためです。構図線は最終結果にも後工程にもほぼ影響しなかったため、v9の凍結土台には含めません。

## ストローク語彙

候補は新しい座標を生成せず、v7の実ストロークから作ります。

1. `paintLoadId` がある4〜7筆程度の局所作業単位は、そのまとまりをそのまま候補にする
2. `face_structure` 初期パスのうち `paintLoadId` がない `face-plane` は、近接した数筆だけをマイクロバンドル化する
3. 色、始点終点、幅、透明度、ブラシ種はv7の値を変更しない

候補の分類は `plane / structure / edge / accent / blend` とし、AIは「頬の面をつなぐ」「目まわりの構造を作る」のような意味だけ指定します。

## 視覚レビューのループ

1. 現在画を表示する
2. AIが座標なしの意図カードを書く
3. コードがv7語彙からA/B/Cの小さな候補を出す
4. 参照画・現在画・A/B/Cを横並びでAIが見る
5. AIが1つを採用、または全却下する
6. 採用したバンドルだけを現在画へ追加する
7. 次の意図を決める

重要部では1バンドル4〜7筆程度を基本とし、必要ならさらに小さくします。

## 禁止事項

- AIが `x/y/bbox/points/segments/angle_deg` などの低レベル座標を書く
- 参照画像とのピクセル誤差を使ってA/B/Cの勝者を自動決定する
- 候補にない新しいストローク座標をAI指示から合成する
- 工程名を満たすためだけにMixer / Smudge / Glazeを使う
- 採用理由がないのに候補を積み上げる

## 成功条件

- 同じv7の線資産を使いながら、v7より少ない後半ストロークで顔が成立する
- AIの座標指定誤差が結果に入らない
- A/B/Cの採否が見た目の改善に直接反映される
- 「細部工程だから描く」ではなく、必要な仕事がなくなった時点で止められる
