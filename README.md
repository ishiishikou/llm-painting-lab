# llm-painting-lab

LLMに与えるプロンプト、ツール、状態保持、参照情報、反復フィードバックの設計によって、視覚的なアウトプット品質をどこまで引き上げられるかを検証する実験用リポジトリです。

目的は、モデル同士を同一条件で公平にベンチマークすることではありません。より弱い／安価なモデルでも、実行環境側で十分な足場を与えることで、より上位のモデルのアウトプットへどこまで近づけられるかを確認します。

## 現在の実験モード

### 1. 厳密モード

既存の `strokes.json` をそのまま再生します。

- 元画像の PNG/JPEG を Canvas に読み込まない
- ストローク文書内に画像URLを持たせない
- 出力は順序付きストロークだけから再構築する
- `npm run validate` で代表的な画像参照用キーを拒否する

このモードは「モデルが構図・形状・色・筆致まで自力で決める場合」の基準になります。

### 2. 参照画像ガイドモード

今回追加した実験です。

参照画像を前処理で解析し、色・輪郭・局所勾配を順序付きブラシストロークへ変換します。最終的な Canvas は元画像を読み込まず、生成済みストロークだけを再生します。

```text
参照画像
  ↓
局所色・勾配を解析
  ↓
輪郭方向に沿ったストロークを生成
  ↓
strokes.generated.json
  ↓
Canvasで1本ずつ再生
```

これは公平なモデル比較のための条件ではありません。モデルに不得意な「細かな形状と色の機械的再現」を環境へ移し、モデルが参照選定、構図、評価、修正方針などへ推論資源を使えるようにするための実験です。

## ブラシ

現在のレンダラーは以下を扱えます。

- `line`
- `curve`
- `dab`
- `softDab`
- `dryBrush`
- `ellipse`
- `pathFill`
- `pathStroke`

高レベルな形状プリミティブを増やす理由は、モデルに生のピクセル操作をさせず、構図・明暗・色面・輪郭といった高レベル判断へ推論を集中させるためです。

## 参照画像ガイド描画を生成する

Python 3 と Pillow が必要です。

```bash
python tools/reference_to_strokes.py reference.jpg \
  --output strokes.generated.json \
  --preview preview.png \
  --detail 28000
```

生成後、ローカルサーバーを起動します。

```bash
npm run serve
```

以下を開くと参照画像ガイド版を再生できます。

```text
http://127.0.0.1:8000/?mode=generated
```

通常の厳密モードは以下です。

```text
http://127.0.0.1:8000/
```

## GitHub Actions

`reference-demo` ワークフローでは、公開されている《真珠の耳飾りの少女》の参照画像を取得し、次を自動生成します。

- `preview.png`
- `strokes.generated.json`
- `strokes.generated.json.gz`
- 再生用Webビューア一式

成果物は `reference-guided-demo` artifact として保存します。

参照画像は成果物の生成時だけ利用し、リポジトリには保存しません。《真珠の耳飾りの少女》自体はパブリックドメインであり、参照元として Mauritshuis / Wikimedia Commons の公開画像を利用します。

## 次に検証すること

単純にストローク数を増やすことではなく、次のループを自動化します。

```text
計画
  ↓
描画
  ↓
レンダリング結果を確認
  ↓
最大の品質ボトルネックを特定
  ↓
局所修正
  ↓
再評価
```

その後、以下を追加する予定です。

- チェックポイント保存
- 領域単位の評価
- Painter / Critic の役割分離
- 参照画像との構造差分評価
- 修正パスの自動生成
- 品質が改善しなくなった時点で停止する収束判定

## 実験上の考え方

このリポジトリで確認したいのは「モデル単体の能力」ではなく、モデルと環境を合わせたシステム全体の能力です。

環境側で機械的な負担をできるだけ引き受け、モデルが高レベルの視覚判断と改善判断へ推論資源を使える状態を作ります。
