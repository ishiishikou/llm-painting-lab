# llm-painting-lab

LLMに与えるプロンプト、ツール、状態保持、参照情報、反復フィードバックの設計によって、視覚的なアウトプット品質をどこまで引き上げられるかを検証する実験用リポジトリです。

目的は、モデル同士を同一条件で公平にベンチマークすることではありません。モデル単体では上位モデルに届かない場合でも、実行環境側で十分な足場を与えることで、システム全体としてアウトプットをどこまで近づけられるかを確認します。

## 現在の実験モード

### 1. 厳密モード

既存の `strokes.json` をそのまま再生します。

- 元画像の PNG/JPEG を Canvas に読み込まない
- ストローク文書内に画像URLを持たせない
- 出力は順序付きストロークだけから再構築する
- `npm run validate` で代表的な画像参照用キーを拒否する

このモードは「モデルが構図・形状・色・筆致まで自力で決める場合」の基準です。

### 2. 参照画像ガイド + 反復修正モード

参照画像を前処理で解析し、色・輪郭・局所勾配を順序付きブラシストロークへ変換します。最終的な Canvas は元画像を読み込まず、生成済みストロークだけを再生します。

現在は、初期描画の後に実際のレンダリング結果を参照画像と比較し、残差が大きい場所へ修正ストロークを追加するところまで自動化しています。

```text
参照画像
  ↓
局所色・勾配を解析
  ↓
下塗り → 中間描画 → 形状精密化 → 細部
  ↓
一度レンダリング
  ↓
参照画像との残差を計測
  ↓
誤差が大きい領域へ修正ストロークを追加
  ↓
再レンダリング・再評価
  ↓
Canvasで全ストロークを順番に再生
```

### 3. 人間らしい描画順モード

品質優先で生成したストロークをそのまま上から下へ走査するのではなく、人が絵を描くときに近い順序へ再構成します。

```text
大きな形を置く
  ↓
明暗の面を作る
  ↓
形と顔の構造を整える
  ↓
目・鼻・口・布・真珠を描き込む
  ↓
重要部を見直す
  ↓
最終仕上げ
```

さらに各工程の中でも、画面全体を機械的に走査しません。背景、衣服、ターバン、顔、真珠・ハイライトなどの領域に分け、1つの局所領域をある程度描いてから近い領域へ移ります。同じ領域では太く長いストロークを先に置き、細い筆致を後から重ねます。

`tools/reorder_painterly.py` がこの並べ替えを担当します。

## 現在の結果

《真珠の耳飾りの少女》を 864x1024 のキャンバスで生成した現在の標準実験では、最終的に 126,446 ストロークを使用しています。

| 指標 | 最終値 |
| --- | ---: |
| MAE | 6.6193 |
| PSNR | 28.0190 dB |
| エッジ誤差 | 21.1881 |

完成画像を貼り付ける方式ではなく、最終Canvasは全ストロークを順番に描画して再構築します。

## ブラシ

現在のレンダラーは以下を扱えます。

- `line`
- `curve`
- `dab`
- `softDab`
- `dryBrush`
- `ellipse`
- `pathFill`
- `pathStroke`

高レベルな形状プリミティブを増やす理由は、モデルに生のピクセル操作をさせず、構図・明暗・色面・輪郭といった高レベル判断へ推論を集中させるためです。

## ローカル実行

参照画像ガイド描画を生成します。

```bash
python tools/reference_to_strokes.py reference.jpg \
  --output strokes.generated.json \
  --preview preview.png \
  --metrics metrics.json \
  --width 864 \
  --height 1024 \
  --detail 24000 \
  --repair 18000
```

人間らしい描画順へ並べ替えます。

```bash
python tools/reorder_painterly.py strokes.generated.json \
  --output strokes.painterly.json
```

ローカルサーバーを起動します。

```bash
npm run serve
```

人間らしい描画順版:

```text
http://127.0.0.1:8000/?mode=painterly
```

参照画像ガイド版:

```text
http://127.0.0.1:8000/?mode=generated
```

厳密モード:

```text
http://127.0.0.1:8000/
```

## リプレイ動画

`tools/render_replay_video.py` で進捗表示付きMP4を生成できます。

```bash
python tools/render_replay_video.py strokes.painterly.json \
  --output replay-painterly.mp4 \
  --seconds 75 \
  --fps 12
```

日本語フォントを明示的に読み込むため、進捗表示の文字化けを防ぎます。動画には現在のストローク数、進捗率、工程、現在描いている領域を表示します。

## GitHub Actions

`reference-demo` ワークフローでは、公開されている《真珠の耳飾りの少女》の参照画像を取得し、次を自動生成します。

- `preview.png`
- `strokes.generated.json`
- `strokes.painterly.json`
- それぞれのgzip版
- `metrics.json`
- `replay-painterly.mp4`
- 再生用Webビューア一式

成果物は `reference-guided-demo` artifact として保存します。

参照画像は成果物の生成時だけ利用し、リポジトリには保存しません。《真珠の耳飾りの少女》自体はパブリックドメインであり、参照元として Mauritshuis / Wikimedia Commons の公開画像を利用します。

## 次に検証すること

すでに `描画 → 評価 → 修正 → 再評価` と、人間に近い描画順への再構成までは成立しています。次は、描き方そのものをさらに人間寄りにします。

- 序盤の面塗りを短線の集合ではなく、長い筆致・大きな色面で構成する
- 顔、目、口、耳飾りなど重要領域への重み付け
- 画素誤差だけでなく輪郭・構造を守る評価関数
- Painter / Critic の役割分離
- 複数候補を生成して最良案を選ぶ探索
- 改善が止まった時点で終了する収束判定

## 実験上の考え方

このリポジトリで確認したいのは「モデル単体の能力」ではなく、モデルと環境を合わせたシステム全体の能力です。

環境側で機械的な負担をできるだけ引き受け、モデルが高レベルの視覚判断と改善判断へ推論資源を使える状態を作ります。
