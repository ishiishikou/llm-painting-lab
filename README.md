# llm-painting-lab

LLMに与えるプロンプト、ツール、状態保持、参照情報、反復フィードバックの設計によって、視覚的なアウトプット品質をどこまで引き上げられるかを検証する実験用リポジトリです。

目的は、モデル同士を同一条件で公平にベンチマークすることではありません。モデル単体では上位モデルに届かない場合でも、実行環境側で十分な足場を与えることで、システム全体としてアウトプットをどこまで近づけられるかを確認します。

## 現在の標準実験: 画家に近い6段階の描画工程

現在の《真珠の耳飾りの少女》実験では、完成後にストロークを並べ替えるのではなく、**ストローク生成そのもの**を次の6工程に分けています。

1. **構図**
   - 顔中心、目線、口位置、肩の流れ、輪郭の目安だけを少数の線で置く
2. **大きな形**
   - 円形スタンプは使わず、長く太い筆致で人物、ターバン、衣服の塊を置く
3. **明暗の面**
   - 大きな色面と光・影を太い筆から順に重ねる
4. **顔構造**
   - 顔の中心線・目線・口位置を取り直し、顔面の立体を独立して整える
5. **細部**
   - 目、鼻、口、布、真珠、輪郭など高コントラスト部分を局所的に描き込む
6. **仕上げ**
   - 一度レンダリングした結果と参照画像の残差を見て、人物領域の誤差が大きい箇所だけを追加修正する

```text
構図
  ↓
大きな形
  ↓
明暗の面
  ↓
顔構造
  ↓
細部
  ↓
仕上げ
```

重要なのは、**フェーズ名を後から付けているだけではない**ことです。GitHub Actionsでは、全ストロークを走査してこの6工程がそれぞれ連続した1ブロックとして、上記の順に並んでいることを自動検証します。

## v2で修正したこと

初期の6段階版は、描画順は正しくても、シルエット工程が円形スタンプの格子状描画に見え、背景の細かな更新に動画時間を使っていました。

現在のv2では次を修正しています。

- `ellipse` による円形スタンプを廃止
- 大きな形は長く太いフラットな筆致でブロックイン
- 明暗の面も人物領域へ長い筆致を重ねる
- 背景は「地塗り」として最初から置き、進捗ストロークから外す
- 動画側でも人物の外接範囲から外れた細かな更新を描画しない
- 動画再生を総ストローク数比例から**工程ごとの時間配分**へ変更
- 進捗表示を「全ストローク中の何%」ではなく**工程内進捗**へ変更

標準動画の時間配分:

| 工程 | 割合 |
| --- | ---: |
| 構図 | 10% |
| 大きな形 | 16% |
| 明暗の面 | 25% |
| 顔構造 | 15% |
| 細部 | 23% |
| 仕上げ | 11% |

これにより、構図が一瞬で消費されることや、背景がほとんど変わらないのに進捗だけ進む問題を抑えます。

## 現在の結果

864x1024 のキャンバスで、v2の本番生成結果は次のとおりです。

| 工程 | 累積ストローク数 | 工程内ストローク数 |
| --- | ---: | ---: |
| 構図 | 10 | 10 |
| 大きな形 | 927 | 917 |
| 明暗の面 | 5,140 | 4,213 |
| 顔構造 | 8,839 | 3,699 |
| 細部 | 38,839 | 30,000 |
| 仕上げ | 56,839 | 18,000 |

最終品質指標:

| 指標 | 最終値 |
| --- | ---: |
| MAE | 8.8171 |
| PSNR | 25.4186 dB |
| エッジ誤差 | 20.8484 |

以前の約10万ストローク版より画素忠実度は下がっていますが、今回の優先目標は**完成画だけでなく、途中経過も画家の作業として自然に見えること**です。完成画像そのものをCanvasへ貼り付ける方式ではなく、最終Canvasは `strokes.generated.json` のストロークから再構築します。

## チェックポイント

`tools/reference_to_human_strokes.py` は、6工程の終了時点をそれぞれPNGとして保存できます。

```text
01-composition.png
02-silhouette.png
03-light-shadow.png
04-face-structure.png
05-detail.png
06-finish.png
```

これにより、最終画像だけでなく、実際にどの順で絵が立ち上がったかを確認できます。

## リプレイ動画

`tools/render_replay_video.py` で、工程ごとの時間配分を使った進捗表示付きMP4を生成します。

```bash
python tools/render_replay_video.py strokes.generated.json \
  --output replay-human-order.mp4 \
  --seconds 82 \
  --fps 10 \
  --width 640
```

動画には次を表示します。

- 現在の工程番号
- 現在の工程名
- 工程内進捗
- 背景は地塗りとして扱う旨

GitHub Actionsでは `fonts-noto-cjk` を明示的に導入し、日本語の文字化けを防ぎます。

## 参照画像から6工程ストロークを生成する

Python 3 と Pillow が必要です。

```bash
python tools/reference_to_human_strokes.py reference.jpg \
  --output strokes.generated.json \
  --preview preview.png \
  --metrics metrics.json \
  --checkpoint-dir checkpoints \
  --width 864 \
  --height 1024 \
  --detail 30000 \
  --finish 18000
```

## Webビューア

ローカルサーバーを起動します。

```bash
npm run serve
```

6工程版:

```text
http://127.0.0.1:8000/?mode=generated
```

厳密モード:

```text
http://127.0.0.1:8000/
```

既存の `tools/reorder_painterly.py` と `?mode=painterly` は、過去の「生成済みストロークを後から人間らしい順へ並べ替える」実験を再現するために残しています。現在の標準実験では使用しません。

## ブラシ

Webレンダラーは以下を扱えます。

- `line`
- `curve`
- `dab`
- `softDab`
- `dryBrush`
- `ellipse`
- `pathFill`
- `pathStroke`

v2の標準生成器では、序盤の大きな形に `ellipse` は使わず、太く長い `line` ストロークをフラットブラシとして利用します。

## GitHub Actions

`reference-demo` ワークフローでは、公開されている《真珠の耳飾りの少女》の参照画像を取得し、次を自動生成します。

- `preview.png`
- `strokes.generated.json`
- `metrics.json`
- `checkpoints/01-composition.png` ～ `06-finish.png`
- `replay-human-order.mp4`
- 再生用Webビューア一式

成果物は `human-painting-order-demo` artifact として保存します。

参照画像は成果物の生成時だけ利用し、リポジトリには保存しません。

## 厳密モード

既存の `strokes.json` をそのまま再生するモードです。

- 元画像のPNG/JPEGをCanvasに読み込まない
- ストローク文書内に画像URLを持たせない
- 出力は順序付きストロークだけから再構築する
- `npm run validate` で代表的な画像参照用キーを拒否する

このモードは「モデルが構図・形状・色・筆致まで自力で決める場合」の基準として残しています。

## 次に検証すること

描画順と序盤のブロックインは人間の作業へかなり近づきました。次に効く改善候補は次です。

- 太筆を1本ずつ途中まで伸びるように動画上でアニメーションする
- 顔構造で目・鼻・口のランドマーク推定をさらに精密化する
- 明暗の面を局所線の集合ではなく、さらに少ない大筆でまとめる
- 画素誤差だけでなく輪郭・構造を守る評価関数を強化する
- Painter / Critic の役割分離
- 複数候補を生成し、最良案を選ぶ探索
- 改善が止まった時点で終了する収束判定

## 実験上の考え方

このリポジトリで確認したいのは「モデル単体の能力」ではなく、モデルと環境を合わせたシステム全体の能力です。

環境側で機械的な負担をできるだけ引き受け、モデルが構図、明暗、色、形状、評価、修正方針といった高レベルの判断へ推論資源を使える状態を作ります。
