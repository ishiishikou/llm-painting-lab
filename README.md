# llm-painting-lab

LLMに与えるプロンプト、ツール、状態保持、参照情報、反復フィードバックの設計によって、視覚的なアウトプット品質をどこまで引き上げられるかを検証する実験用リポジトリです。

目的は、モデル同士を同一条件で公平にベンチマークすることではありません。モデル単体では上位モデルに届かない場合でも、実行環境側で十分な足場を与えることで、システム全体としてアウトプットをどこまで近づけられるかを確認します。

## 現在の実験モード

### 1. 厳密モード

既存の `strokes.json` をそのまま再生します。

- 元画像の PNG/JPEG を Canvas に読み込まない
- ストローク文書内に画像URLを持たせない
- 出力は順序付きストロークだけから再構築する
- `npm run validate` で代表的な画像参照用キーを拒否する

このモードは「モデルが構図・形状・色・筆致まで自力で決める場合」の基準です。

### 2. 参照画像ガイド + 反復修正モード

参照画像を前処理で解析し、色・輪郭・局所勾配を順序付きブラシストロークへ変換します。最終的な Canvas は元画像を読み込まず、生成済みストロークだけを再生します。

現在は、初期描画の後に実際のレンダリング結果を参照画像と比較し、残差が大きい場所へ修正ストロークを追加するところまで自動化しています。

```text
参照画像
  ↓
局所色・勾配を解析
  ↓
下塗り → 中間描画 → 形状精密化 → 細部
  ↓
一度レンダリング
  ↓
参照画像との残差を計測
  ↓
誤差が大きい領域へ修正ストロークを追加
  ↓
再レンダリング・再評価
  ↓
Canvasで全ストロークを順番に再生
```

これは公平なモデル比較のための条件ではありません。モデルに不得意な「細かな形状と色の機械的再現」や「誤差の探索」を環境へ移し、モデルが参照選定、構図、評価、修正方針などへ推論資源を使えるようにするための実験です。

## 現在の結果

《真珠の耳飾りの少女》を対象にした GitHub Actions の実行では、次のように改善しました。

| 段階 | ストローク数 | MAE | PSNR |
| --- | ---: | ---: | ---: |
| 初期描画 | 103,055 | 7.0831 | 27.1628 dB |
| 残差修正1 | 115,055 | 6.6890 | 27.9080 dB |
| 残差修正2 | 123,055 | 6.6560 | 27.9428 dB |

画素誤差は改善しています。一方、エッジ誤差は初期描画よりわずかに悪化したため、数値だけを最適化するのではなく、最終的な見た目も含めて評価します。

## ブラシ

現在のレンダラーは以下を扱えます。

- `line`
- `curve`
- `dab`
- `softDab`
- `dryBrush`
- `ellipse`
- `pathFill`
- `pathStroke`

高レベルな形状プリミティブを増やす理由は、モデルに生のピクセル操作をさせず、構図・明暗・色面・輪郭といった高レベル判断へ推論を集中させるためです。

## 参照画像ガイド描画を生成する

Python 3 と Pillow が必要です。

```bash
python tools/reference_to_strokes.py reference.jpg \
  --output strokes.generated.json \
  --preview preview.png \
  --metrics metrics.json \
  --detail 28000 \
  --repair 20000
```

生成後、ローカルサーバーを起動します。

```bash
npm run serve
```

参照画像ガイド版:

```text
http://127.0.0.1:8000/?mode=generated
```

厳密モード:

```text
http://127.0.0.1:8000/
```

## GitHub Actions

`reference-demo` ワークフローでは、公開されている《真珠の耳飾りの少女》の参照画像を取得し、次を自動生成します。

- `preview.png`
- `strokes.generated.json`
- `strokes.generated.json.gz`
- `metrics.json`
- 再生用Webビューア一式

成果物は `reference-guided-demo` artifact として保存します。

参照画像は成果物の生成時だけ利用し、リポジトリには保存しません。《真珠の耳飾りの少女》自体はパブリックドメインであり、参照元として Mauritshuis / Wikimedia Commons の公開画像を利用します。

## 次に検証すること

すでに `描画 → 評価 → 修正 → 再評価` までは成立しています。次は、修正方法そのものを改善します。

- 画素誤差だけでなく輪郭・構造を守る評価関数
- 顔、目、口、耳飾りなど重要領域への重み付け
- Painter / Critic の役割分離
- 複数候補を生成して最良案を選ぶ探索
- 改善が止まった時点で終了する収束判定

## 実験上の考え方

このリポジトリで確認したいのは「モデル単体の能力」ではなく、モデルと環境を合わせたシステム全体の能力です。

環境側で機械的な負担をできるだけ引き受け、モデルが高レベルの視覚判断と改善判断へ推論資源を使える状態を作ります。
